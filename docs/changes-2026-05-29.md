# Changes — 2026-05-29

## RViz startup

**Before:** RViz launched from `movement.launch.py` at `t=12s` (TimerAction).  
**After:** `scripts/launch.py` fires RViz immediately after the dashboard — before Phase 1 (UR driver) even starts — so it loads in the background while the robot initialises.

- When `--perception` is active: uses `holoassist_full.rviz` from the perception package.
- `perception.launch.py` always passes `start_rviz:=false` (avoids second instance).
- Movement standalone (no `--perception`) is unchanged — movement still owns RViz in that path.

## RViz config — MotionPlanning plugin removed

`holoassist_full.rviz` had `moveit_rviz_plugin/MotionPlanning` (enabled: false) which still loaded the plugin shared library on startup. Commented out. Use the interactive MoveIt panel only if needed — uncomment to restore.

**Remaining displays:** Grid, RobotModel, Trolley (MarkerArray), Cube 1–4 (Marker ×4), TF, Image (debug_image).

## AprilTag detector threads

`apriltag_cubes.yaml`: `detector.threads` raised from `2` → `4`.  
`detector.decimate` stays at `1.0` (full resolution).

## Dashboard — tab bar

Tab `min-width` raised from `72px` → `90px` so `CALIBRATION` is no longer clipped.

## Dashboard — Camera tab

Resolution preset dropdown (`QComboBox`) removed. Feature was broken:
- RealSense doesn't support mid-stream profile changes via `ros2 param set`.
- Webcam node reads params only at init — no dynamic reconfigure callback exists.

Dead code removed from: `main.py` (CameraScreen), `ros_interface.py` (`reconfigure_camera`, `_camera_reconfigure_pub`), `bridge_server.py` (`reconfigure_camera` handler), `net_interface.py` (`reconfigure_camera` relay).

## Dashboard — Debug tab overhaul

### Removed
- **Latency text strip** ("Jt age / Cmd age / Interval" bar) — information already shown in graphs.

### TOPIC HEALTH graph
Added 4th series: **camera** (teal `#39c5bb`) tracking `debug_image` topic at expected 30 Hz.  
Now: joints (green) · vel_cmd (blue) · headset (orange) · camera (teal).  
Title shows: `jt=X% vel=X% cam=X%`.

### VIDEO FEED FPS graph (new, replaces CAMERA FPS + CAMERA TOPIC HEALTH)
Full-width bottom row. Two series:
- **camera** (blue) — `debug_image` Hz
- **headset** (orange) — `headset_image` Hz

Title shows live: `cam=X.X  hmd=X.X`.

### Data pipeline
`camera_fps_history` → `video_fps_history`.  
Each sample: `(t, [cam_hz, headset_hz])`. Sampled at 2 Hz in `_sample_rates`, passed through `ros_interface → bridge_server → net_interface → DebugScreen`.
