Overview

System overview

HoloAssist integrates a Meta Quest 3 headset with a UR3e collaborative robot for real-time teleoperation, autonomous pick-and-place, and spatial AR visualisation. AprilTag-equipped cubes are detected at 20 Hz; MoveIt 2 drives the physical arm; Unity on the Quest 3 renders a holographic twin and accepts XR controller teleop commands over ROS-TCP-Endpoint.

Quick Start

One command to launch

Run from the main repository. The current launcher enables perception, MoveIt, RViz, and the dashboard by default.

cd /home/john/git/RS2-HoloAssist/main # Fake hardware — full stack defaults ./scripts/launch.sh # Real robot — full stack defaults ./scripts/launch.sh --robot-ip 192.168.0.194 # URSim (simulated robot, Docker) ./scripts/launch.sh --robot-ip 192.168.56.101 --fake-gripper # Teleop controllers instead of MoveIt controllers ./scripts/launch.sh --robot-ip 192.168.0.194 --no-moveit
First time? Run calibration after moving the camera or robot base: ./scripts/calibrate.sh --robot-ip 192.168.0.194

Launch Flags

All available flags

Option A

Real Robot

Default IP: 192.168.0.194 — check the robot touchscreen if different.

# Teleop only ./scripts/launch.sh --robot-ip 192.168.0.194 # Teleop mode: MoveIt off, velocity controllers active ./scripts/launch.sh --robot-ip 192.168.0.194 --no-moveit # Narrow run without camera perception ./scripts/launch.sh --robot-ip 192.168.0.194 --no-perception

The launcher prints the WiFi IP at startup — enter that in the Unity Quest app under ROS Settings, port 10000.

Always-on processes: UR + OnRobot driver, trolley scene publisher, ROS-TCP endpoint (:10000), and IP beacon (UDP multicast for Quest auto-discovery) start regardless of flags.
Option B

URSim (Docker Simulator)

Use when the physical robot is not available. URSim runs Polyscope at 192.168.56.101 over a VirtualBox host-only network.

Step 1 — Start URSim

docker run --rm -it \ -p 5900:5900 -p 6080:6080 \ -p 29999:29999 -p 30001-30004:30001-30004 \ -p 50001-50002:50001-50002 \ --name ursim \ universalrobots/ursim_e-series

Wait for Polyscope started, then open Polyscope at http://localhost:6080 (noVNC). Navigate to Run Program → External Control. Do not click Play yet.

Step 2 — Launch

cd /home/john/git/RS2-HoloAssist/main ./scripts/launch.sh --robot-ip 192.168.56.101 --fake-gripper
--fake-gripper is required with URSim. URSim does not expose port 54321 (OnRobot serial relay). Without it, the controller manager blocks indefinitely.

Once the launcher settles, click Play in Polyscope. The log confirms: Robot connected to reverse interface. Ready to receive control commands.

Option C

Fully Fake Hardware

No robot IP = fake hardware mode. Perception, MoveIt, dashboard, RViz, ROS-TCP-Endpoint, and the IP beacon still start unless explicitly disabled.

cd /home/john/git/RS2-HoloAssist/main ./scripts/launch.sh
Dashboard

E-stop & monitoring dashboard

PyQt5 dashboard designed for 1280×800 (Steam Deck). Tabs: Status · Headset · Graph · Stats · Latency · Session.

# Launch standalone ./dashboard.sh ./dashboard.sh --fullscreen # Connect remotely from Steam Deck or another machine ./dashboard.sh --bridge ws://192.168.0.xxx:9090

In normal mode, also starts bridge_server.py on port 9090 (WebSocket) for remote dashboard clients.

E-stop: Burst-publishes [0,0,0,0,0,0] × 10 to /forward_velocity_controller/commands, then switches controllers off. Hold RESUME for 5 s to re-enable.
Quest 3

Connecting the Quest 3

  1. Connect Quest and laptop to the same WiFi network.
  2. Note the WiFi IP printed by the launcher at startup.
  3. In the Unity app: open ROS Settings → set host IP to that address.
  4. TCP scanning auto-discovers the ROS bridge on the network.
  5. ROS-TCP-Endpoint listens on port 10000.

Stopping

Stopping the System

Ctrl+C in the launcher terminal. The launcher sends SIGTERM, waits 2 s, then SIGKILLs all child processes.

If processes remain:

pkill -9 -f ur_ros2_control_node pkill -9 -f move_group

Monitoring Logs

All logs go to /tmp/holoassist_*.log:

# UR driver tail -f /tmp/holoassist_ur_onrobot_driver.log | grep -E "connected|error|failed|RTDE" # AprilTag detection tail -f /tmp/holoassist_cube_pose.log # MoveIt tail -f /tmp/holoassist_moveit.log
Known Issues

Troubleshooting

  • URSim WiFi disconnect If the laptop’s WiFi drops, RTDE is lost. Stop Program in Polyscope, Ctrl+C the launcher, re-run, then click Play again.
  • “Receive program failed: 192.168.56.1:50002” Driver failed before port 50002 was ready. Restart the launcher first, then click Play.
  • High CPU after Ctrl+C Zombie ur_ros2_control_node processes. Run: pkill -9 -f ur_ros2_control_node
  • Arm not visible in RViz Robot description takes ~15 s. If nothing after 30 s, check tail -f /tmp/holoassist_ur_onrobot_driver.log
  • Cubes not visible in RViz Point the camera at a cube face until the marker appears. Confirm /detections and /holoassist/perception/debug_image are updating, then check the cube pose topic.
