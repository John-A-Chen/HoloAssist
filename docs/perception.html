Overview

What this subsystem does

The perception subsystem tracks up to 4 physical 40 mm cubes using AprilTag stickers (36h11 family, 32 mm printed size). Each cube has 6 tags — one per face — with IDs grouped into four physical cubes (IDs 10–33). A cube is detected as soon as any single face is visible.

When multiple faces are visible, a consensus filter averages candidate centres within 5 cm of each other, rejecting outliers. A 3 mm deadzone suppresses jitter. Once detected, the last known position is frozen in RViz even after tags leave the camera frame.

Cube poses are resolved into the robot base_link frame using the saved easy_handeye2 calibration (base_link → camera_link transform). Poses are also relayed to Unity so the Quest 3 XR scene can display cube holograms at the correct physical locations.

Data Flow

From camera to cube poses

The full pipeline from raw camera frames to Unity cube holograms and MoveIt grasp targets.

Camera colour stream (any supported camera) │ /camera/color/image_raw ▼ apriltag_ros [36h11 family · tag size 0.032 m] │ /detections ▼ holoassist_cube_pose_node [20 Hz timer — TF-safe] │ /holoassist/perception/april_cube_N_pose ← base_link frame │ /holoassist/perception/april_cube_N_marker ← RViz colour-coded marker │ /holoassist/perception/april_cube_N_status │ /holoassist/perception/april_cube_N_bin_check ▼ cube_pose_relay.py │ /holoassist/unity/cube_N_pose ← Unity-friendly relay ▼ MoveIt pick-and-place · Quest 3 Unity (CubePoseSubscriber.cs)

The static base_link → camera_link transform is published from the saved easy_handeye2 calibration file, giving the full TF chain: world → base_link → camera_link → camera_color_optical_frame → tag36h11:XX.

Pipeline

Detection in four stages

01

Camera Capture

Any camera (RealSense D435i, UVC webcam, laptop webcam) via camera_only.launch.py. Publishes /camera/color/image_raw.

›
02

AprilTag Detection

apriltag_ros detects 36h11 tags, publishes /detections with 3D pose in camera frame. Tag IDs 10–33 across four physical cubes (six faces each).

›
03

Cube Pose Fusion

20 Hz timer groups tags by cube ID. Face-to-centre offset (20 mm) applied. Consensus filter averages multi-face estimates within 5 cm. 3 mm deadzone suppresses jitter.

›
04

Bin Verification

Transforms cube XY into base_link frame, checks against bin_poses.json with configurable XY margin. Publishes sorted=true/false on each cube's bin_check topic.

Setup & Calibration

Printing cubes and calibrating the camera

Perception requires a saved camera-to-robot calibration before poses can be resolved into the robot base frame. Recalibrate whenever the camera or robot base moves.

How to Run

Start perception with one command

Perception is integrated with the main launcher. Pass --perception to start the camera, AprilTag detector, cube pose node, and Unity relay in a single launch.

# Confirm calibration file exists first ls ~/.ros2/easy_handeye2/calibrations/holoassist_calibration.calib # Real robot + camera + perception + Unity relay ./launch.sh --robot-ip 192.168.0.192 --perception # Fake hardware + perception only (no real robot required) ./launch.sh --perception

After launch: start External Control on the teach pendant, hit Play in Unity, then place AprilTag cubes (IDs 10–33) in camera view. Cube holograms appear in the Quest 3 scene within 1–2 seconds relative to the ur3e_rg2 robot base.

Known Issues

Troubleshooting

  • No AprilTag detections
    Camera cannot see tags, lighting is poor, or tag size/family is wrong. Check camera angle, lighting, and focus. Confirm tag family is 36h11 and printed size matches 32 mm. Echo /detections --once to verify.
  • Detections but no cube poses
    holoassist_cube_pose_node is not running or tag IDs do not match config/cubes.yaml. Run ros2 node list | grep cube and confirm face IDs 10–33 appear in /detections. The node only merges tags that match known cube ID groups.
  • Cube poses published but not visible in Unity
    The relay is not running or Unity is not connected. Check ros2 topic echo /holoassist/unity/cube_1_pose --once. Unity reads the relayed topics — perception working does not guarantee Unity is receiving them.
  • TF tree disconnected / calibration missing
    Run ros2 run tf2_ros tf2_echo base_link camera_link. If it hangs, re-run calibration or confirm the calibration file exists at ~/.ros2/easy_handeye2/calibrations/holoassist_calibration.calib. Without this transform, cube poses cannot be resolved into base_link.
  • Cubes not visible in RViz after launch
    Cubes only appear after first detection. Point the camera at a cube face until the RViz marker appears — then it persists even if occluded. This is the intended freeze-on-loss behaviour.
  • Cube pose offset or scaled wrong
    The printed AprilTag size does not match cube_tag_size_m: 0.032. Measure the black tag border and update the config. AprilTag pose estimation uses the declared tag size as metric scale — any mismatch causes proportional error in all axes.
  • Bin check false negatives
    If sorted=false when the cube is visually inside the bin, increase bin_xy_margin_m to 0.10 in cubes.yaml. Hand-eye calibration must be loaded — the bin check uses base_link for comparison.
  • Only some cube faces work
    Physical tag IDs are misplaced or do not match config/cubes.yaml. Echo /detections and check which IDs appear. Each cube face must belong to the correct ID group in the config.
Limitations

Assumptions & known limitations

Assumptions

  • AprilTags are printed at exactly 32 mm edge size
  • Each physical cube is 40 mm wide with a 20 mm face-to-centre offset
  • The camera is rigidly mounted during operation — any movement requires recalibration
  • The saved easy_handeye2 calibration correctly publishes base_link → camera_link
  • Cube face IDs match configured groups: Cube 1 (10–15), Cube 2 (16–21), Cube 3 (22–27), Cube 4 (28–33)
  • Cube face tags are mounted in the expected axis order: +X, −X, +Y, −Y, +Z, −Z

Known limitations

  • If the camera or robot base moves, calibration must be repeated before cube poses are valid
  • A cube with zero visible face tags is reported as not detected — no depth-based fallback
  • Pose accuracy depends on printed tag size accuracy, camera intrinsic calibration, and easy_handeye2 calibration quality
  • The system tracks cubes by AprilTag ID only — no object classification or shape-based fallback
  • Unity visualisation depends on both the ROS endpoint and the cube pose relay running correctly

Future work

  • Automatic calibration quality check before launch — warn if transform looks wrong
  • Confidence scoring based on number of visible cube faces
  • Fuse RealSense depth information with AprilTag pose estimates for improved robustness
  • Extend ID groups in cubes.yaml to support more than four cubes
  • Clearer Unity-side diagnostics when ROS connection or pose relay fails
