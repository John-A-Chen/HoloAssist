Overview

What this subsystem does

The perception subsystem tracks up to 4 physical 40 mm cubes using AprilTag stickers (36h11 family, 32 mm printed size). Each cube has 6 tags — one per face — grouped into a cube ID. A cube is detected as soon as any single face is visible.

When multiple faces are visible, a consensus filter averages candidate centres within 5 cm of each other, rejecting outliers. A 3 mm deadzone suppresses jitter. Once detected, the last known position is frozen in RViz even after tags leave the camera frame.

Pipeline

Detection in four stages

01

Camera Capture

Brio 4K at 848×480 / 30 fps. RealSense or generic webcam as fallback. Publishes /camera/color/image_raw.

›
02

AprilTag Detection

apriltag_ros detects 36h11 tags, publishes /detections_all with 3D pose in camera frame.

›
03

Cube Pose Fusion

20 Hz timer groups tags by cube ID. Consensus filter averages multi-face estimates. 3 mm deadzone suppresses jitter.

›
04

Bin Verification

Transforms cube XY into base_link frame, checks against bin_poses.json with configurable margin.

Known Issues

Troubleshooting

  • Cubes not visible in RViz
    Cubes only appear after first detection. Point the Brio at a cube face until the marker appears — then it persists even if occluded.
  • First detection silently dropped
    Fixed: node runs on a 20 Hz timer rather than the detection callback, avoiding the TF race condition that caused the first frame to fail.
  • Bin check false negatives
    If sorted=false when the cube is visually in the bin, increase bin_xy_margin_m to 0.10 in cubes.yaml. Requires calibration to be loaded.
  • No bin check output
    Hand-eye calibration must be loaded so the TF camera_color_optical_frame → base_link exists. Without it the node logs a warning and skips silently.
