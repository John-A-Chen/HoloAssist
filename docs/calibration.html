Overview

What calibration does

The camera must be calibrated relative to the robot base so cube poses are expressed in robot frame. Calibration is performed once and saved to:

~/.ros2/easy_handeye2/calibrations/holoassist_calibration.calib

The launcher reads this at startup and publishes the static TF automatically. Calibration survives reboots — no re-calibration needed unless the camera is physically moved.

Running

Running calibration

cd ~/git/RS2-HoloAssist/main ./calibrate.sh

Uses easy_handeye2 to collect robot pose / camera pose pairs.

Process

  1. Attach a calibration target (AprilTag board) to the robot end-effector
  2. Run ./calibrate.sh — RViz opens with the calibration GUI
  3. Move the arm to each sample pose (the GUI shows where to move)
  4. Press Take Sample at each pose
  5. After 12–15 samples: press Compute → check reprojection error (< 2 mm is good)
  6. Press Save — writes .calib file

Verification

After saving, restart the launcher and check the TF tree:

ros2 run tf2_tools view_frames # Should show: world → base_link → camera_color_optical_frame

Or check the transform directly:

ros2 run tf2_ros tf2_echo base_link camera_color_optical_frame

File Format

Calibration file format

# ~/.ros2/easy_handeye2/calibrations/holoassist_calibration.calib transform: translation: {x: 0.xxx, y: 0.xxx, z: 0.xxx} rotation: {x: 0.xxx, y: 0.xxx, z: 0.xxx, w: 0.xxx} parameters: tracking_base_frame: base_link tracking_marker_frame: camera_color_optical_frame

Bin Verification

Impact on bin verification

  • Without calibration Cube poses published in camera_color_optical_frame (not robot frame). Bin verification silently skips — logs a throttled warning, no crash.
  • With calibration loaded Bin verification activates automatically. The TF lookup camera_color_optical_frame → base_link succeeds and XY bin matching works.
  • When to re-calibrate If the camera is physically moved or remounted. Re-run ./calibrate.sh.
