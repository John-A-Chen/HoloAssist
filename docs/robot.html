External Control

How External Control works

The UR driver uses URScript External Control to take over joint control from Polyscope:

  1. ur_ros2_control_node connects to robot on ports 30001 (primary) and 30004 (RTDE)
  2. Driver uploads the External Control URScript
  3. Polyscope connects back to host on port 50002 to download the script
  4. Robot enters External Control mode — ROS controls joints

If you see “Receive program failed: 192.168.56.1:50002” — the driver hasn’t opened port 50002 yet. Restart the launcher, wait for ✓  UR + OnRobot Driver, then click Play.

MoveIt

Pick-and-place pipeline

MoveIt is enabled by default. The top-level launcher starts ur_onrobot_control start_robot.launch.py first, then launches holoassist_movement movement.launch.py for MoveIt, trajectory execution, and the planning scene. Pass --no-moveit to switch into Unity teleop controller mode.

Cube sorting flow

  1. Perception node detects cube poses → publishes to /holoassist/perception/april_cube_N_pose
  2. pick_place_sequencer reads cube poses and target bin assignments
  3. Plans Cartesian path (primary) → OMPL fallback
  4. Executes: move above cube → close gripper → lift → move to bin → open gripper
  5. Perception node verifies bin: /holoassist/perception/april_cube_N_bin_check

Safety

Safety features

  • MoveIt collision check on every trajectory
  • Floor collision object in planning scene prevents table crashes
  • UR flange-to-forearm clamp check rejects self-collision trajectories
  • Robot status checks before execution (safety mode, program running)
  • E-stop available via the dashboard window (red button)
