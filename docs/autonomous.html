Overview

What this subsystem does

The autonomous subsystem exposes a ROS 2 service that accepts a cube ID and a target bin, plans a collision-aware pick-and-place trajectory using MoveIt 2, and executes it on the UR3e arm. The OnRobot RG2 gripper opens and closes at the appropriate stages.

Cube poses are consumed live from the perception subsystem's /holoassist/perception/april_cube_N_pose topics. The planner uses the scaled_joint_trajectory_controller for smooth, speed-limited execution.

Pipeline

Pick-and-place in four stages

01

Pose Acquisition

Subscribe to perception topic for target cube. Transform pose from camera frame to base_link via TF.

›
02

Pre-grasp Plan

MoveIt plans approach trajectory to pre-grasp waypoint above cube. Collision objects loaded from URDF + scene.

›
03

Grasp + Lift

Arm descends to grasp pose. RG2 closes. Arm lifts to carry height. Object attached to end-effector in planning scene.

›
04

Place + Retreat

Plan to bin target from bin_poses.json. Descend, open gripper, detach object. Retreat to home pose.

Known Issues

Troubleshooting

  • Planning fails immediately
    Ensure hand-eye calibration is loaded so the TF camera_color_optical_frame → base_link exists. Without it, the cube pose transform fails and MoveIt has no valid goal.
  • Arm doesn't move after plan succeeds
    With URSim, External Control must be playing in Polyscope before execution. The driver logs "Robot connected" when ready.
  • Gripper doesn't actuate (URSim)
    URSim does not expose the OnRobot Modbus port. Launch with --fake-gripper flag when using URSim.
  • Place position inaccurate
    Check bin_poses.json XY values against measured bin positions in base_link frame. Recalibrate if drift exceeds ~2 cm.
