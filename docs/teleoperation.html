Overview

What this subsystem does

The teleoperation subsystem lets an operator control the UR3e arm using natural hand gestures tracked by the Meta Quest 3 headset. Unity C# scripts capture hand pose data and publish it over the ROS-TCP-Endpoint bridge running on the laptop.

A UDP beacon broadcasts the laptop IP address so the Quest app can connect without manual configuration. The bridge listens on port 10000. Both joint-space and Cartesian end-effector control modes are supported.

Pipeline

Gesture to motion in four stages

01

Hand Tracking

Quest 3 XR Hand subsystem tracks 26 joints per hand at ~72 Hz. Unity reads poses each frame.

›
02

Gesture Recognition

Unity C# classifies pinch, grip, and directional gestures. Maps to robot commands (joint deltas or Cartesian targets).

›
03

ROS-TCP Bridge

Commands published as ROS messages via ROS-TCP-Connector. UDP beacon handles IP auto-discovery on the same LAN.

›
04

UR3e Execution

ROS-side subscriber forwards commands to the joint trajectory controller or servoing node. E-stop checked on every cycle.

Known Issues

Troubleshooting

  • Quest can't find the robot
    Quest and laptop must be on the same WiFi network. Note the WiFi IP printed at launcher startup and enter it in the Quest Unity app under ROS Settings → Host IP.
  • Connection drops during use
    If WiFi drops, the ROS-TCP connection is lost. Restart the launcher and reconnect the Quest app. The UDP beacon re-broadcasts automatically.
  • Arm unresponsive to gestures
    Check that the UR driver is active (joint_state_broadcaster [active] in the launcher log). With URSim, External Control must be playing.
  • AR overlay misaligned
    Hand-eye calibration must be run and loaded. Without a valid camera_color_optical_frame → base_link TF, cube poses in the headset will be incorrect.
